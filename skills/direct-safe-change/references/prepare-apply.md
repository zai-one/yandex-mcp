# Safe writes: prepare -> approve -> apply -> verify

- Direct campaigns: `direct_prepare_changes(changes)` returns a diff, its hash and `approval_id` (TTL 30 min); the local operator accepts it outside MCP with `uv run python -m zai_yandex.approvals --state-path ... --account ... --principal ... --approval-id UUID --request-hash SHA256 [--named-account NAME] --accept` (see docs/RUNTIME.md); then `direct_apply_changes(..., approval_id, idempotency_key)` (Campaigns.update only); the server re-reads campaigns to confirm.
- Direct, any allowlisted service/method (ads, keywords, bids, keywordbids, bidmodifiers, audience/retargeting, sitelinks, vcards, adimages, adextensions, advideos, creatives, feeds, negative keyword sets, dynamic text/feed and smart targets, strategies, agency clients): `direct_prepare_write(service, method, items)` -> accept -> `direct_apply_write(..., approval_id, idempotency_key)` -> readback. The approval binds service, method, items, account and sandbox/production. `direct_write` is the autonomous idempotent path (write flag, no human approval) and keeps its 0.6.0 allowlist only: campaigns, adgroups, ads (no unarchive), keywords, bids set/setAuto. Every other service/method (keyword bids, bid modifiers, audience/retargeting, sitelinks, images, extensions, videos, creatives, feeds, negative keyword sets, vcards, dynamic text/feed and smart targets, strategies, agency clients, clients, ads unarchive, unified v501 calls) is approval-only.
- Metrika/Webmaster/Audience management (grants, delegates, counters, filters, segments, labels, annotations, uploads, hosts, feeds, Audience segments/pixels): `<p>_manage_prepare` -> accept -> `<p>_manage_apply` -> readback; uncertain -> `<p>_manage_reconcile`. Catalogue: yandex://guide/management.
- Webmaster: `webmaster_prepare_recrawl|sitemap` -> `webmaster_apply_*` with approval_id + idempotency_key; uncertain results -> `webmaster_reconcile_action`.
- Audience: `audience_validate_create` returns `confirmation_hash`; pass it to `audience_create_*`; uncertain -> `audience_reconcile_create`.
- Search API: `yandex_serp_prepare` -> show the cost note -> `yandex_serp_submit` (paid) -> `yandex_serp_status` -> `yandex_serp_get_result`.
Approvals are bound to the account they were prepared for: accept with the same `--named-account` (omit for the default); apply on another account or endpoint fails closed.
Rules: show the exact diff and its cost (units, money, quota) before asking; one approval per change set; reuse the idempotency_key on retry; never "fix" a failed apply by re-preparing a different change silently.
