# Yandex MCP

**Реклама, аналитика и поисковые данные Яндекса — в одном диалоге.**

> MCP-сервер для Яндекс Директа, Метрики (включая Logs API и офлайн-конверсии), Вебмастера, Wordstat, Search API и Аудиторий: 127 инструментов в одном сервере, наборы инструментов, режим только чтения и защищённая запись.

Разбирайте кампании Директа, статистику Метрики, ограниченные сценарии Аудиторий, поисковый спрос и диагностику Вебмастера с одним ассистентом. Yandex MCP объединяет шесть групп API: настройте нужные для вашей задачи сервисы и добавляйте остальные по мере необходимости.

**По умолчанию включены все инструменты (`all`, 127 шт., ~22k токенов на старте сессии).** Чтобы сэкономить токены, выберите платформы через `YANDEX_TOOLSETS` — мастер установки (`yandex-mcp-setup`) или промпт `yandex_setup` спросит, какие нужны, и запишет настройку сам. Измеренная стоимость tools/list + роутер (без ключа Геопоиска):

| Пресет | Платформы | Инструментов | ~Токенов |
|---|---|---|---|
| `everything` (по умолчанию) | все | 127 | 21 986 |
| `seo` | webmaster, wordstat, serp | 55 | 8 971 |
| `direct-only` | direct | 40 | 8 055 |
| `analytics` | metrika, audience | 30 | 5 786 |

## Что можно сделать

| Задача | Возможности MCP |
|---|---|
| Директ | Кампании, поддерживаемые рекламные объекты, пакетные стратегии и статистика, в том числе конверсии и доход по целям; управляемые изменения при включённой записи. |
| Метрика | Счётчики, цели, отчёты с фильтрами, сравнение периодов и CSV со сведениями о выборке. |
| Search API | Асинхронные задания поисковой выдачи Яндекса с сохранёнными результатами. |
| Wordstat | Популярные запросы, динамика спроса, распределение по регионам и дерево регионов. |
| Вебмастер | Индексация и диагностика сайта, история ИКС, важные страницы, события появления и исключения страниц, статистика запросов, работа с sitemap и переобходом. |
| Аудитории | Сегменты и пиксели; защищённое создание окружностей, полигонов, пикселей и сегментов зрителей при явном включении. |

[Примеры отчётов и помощь с OAuth](docs/METRIKA_REPORTS.md#по-русски): сравнение периодов, экспорт и объяснение неполных результатов. [Покрытие API](docs/API_COVERAGE.md#по-русски): новые инструменты со ссылками на документацию Яндекса.

## Почему этот MCP

- Ленивая загрузка инструментов (опционально): `YANDEX_TOOL_LOADING=lazy` (или выбор в мастере настройки) — старт с небольшим ядром, наборы включаются по запросу; см. [Ленивая загрузка инструментов](#ленивая-загрузка-инструментов).
- Шесть групп API Яндекса в одном процессе; включайте только нужные наборы (`YANDEX_TOOLSETS`, `YANDEX_READ_ONLY`). Редкие чтения — в отдельных наборах `direct_extra` (клиент, справочники, Changes, ставки, корректировки, аудитории, ретаргетинг, фиды, креативы, уточнения, турбо-страницы, лиды, видео, наборы минус-фраз) и `webmaster_extra` (владельцы, фиды, регионы, аналитика запросов); в пресет `default` они не входят (без `YANDEX_TOOLSETS` включены все 127 инструментов; выбрать платформы: `yandex_setup_toolsets`, пишет только `YANDEX_TOOLSETS` в `mcp.local.json`, затем перезапуск клиента). Поиск организаций Яндекс Карт (`maps_geosearch`: `maps_search_organizations`, `maps_search_places`) появляется только при заданном `YANDEX_MAPS_GEOSEARCH_API_KEY` (или `YANDEX_MAPS_GEOSEARCH_API_KEY_FILE`); результаты не кэшируются, атрибуция Яндекса сохраняется. Администрирование — в наборах `metrika_manage`, `webmaster_manage`, `audience_manage` (доступы, представители, счётчики, фильтры, сегменты, метки, примечания, загрузки звонков/расходов/параметров, сайты, фиды, сегменты Аудиторий); все записи через prepare -> согласование -> apply. Сравнение с конкурентами: [docs/COVERAGE_DIFF.md](docs/COVERAGE_DIFF.md). Запуск без `--config`: `uvx --from "zai-yandex-mcp[standalone] @ git+https://github.com/zai-one/yandex-mcp@main" yandex-mcp`, затем попросите ассистента подключить Яндекс (OAuth device flow).
- Запись (изменения в Директе, создание сегментов Аудиторий, загрузки и Logs-запросы Метрики) выключена, пока не включена переменной окружения, и использует хэши подтверждения или ключи идемпотентности.
- Агентский слой: инструкции-роутер, 4 промпта, ресурсы `yandex://playbook` и гайды, самодостаточные skills, структурированные ошибки с `hint`.
- Сравнение с другими Yandex MCP на GitHub: [SvechaPVL/yandex-mcp](https://github.com/SvechaPVL/yandex-mcp) (132), [skiddgoddamn/yandex-marketing-mcp](https://github.com/skiddgoddamn/yandex-marketing-mcp) (153) и [webkoth/yandex-mcp](https://github.com/webkoth/yandex-mcp) (125) по-прежнему показывают больше *инструментов* (часто add/update/delete отдельно); этот сервер закрывает документированные **чтения** Direct+Webmaster, которые важны на практике, держит запись за флагами по сервисам и отдаёт ограниченные типизированные ответы; CI на Linux и Windows.

## Ленивая загрузка инструментов

Ленивая загрузка инструментов (опционально): `YANDEX_TOOL_LOADING=lazy` стартует с небольшим ядром и `yandex_enable_toolsets`, остальные наборы включаются по запросу (`tools/list_changed`). Стоимость старта (tools/list + instructions, ≈символы/4): eager ≈21872 токенов, lazy ≈2574 токенов (−88%). По умолчанию `eager` — без изменений; если клиент не поддерживает `tools/list_changed`, оставьте `eager` или переподключитесь после включения. Область: включение действует в пределах MCP-сессии (session visibility FastMCP), включённые одним клиентом наборы не видны другому. HTTP-транспорт здесь stateless (каждый запрос — отдельная сессия), поэтому включение там не сохраняется: для общего HTTP используйте `eager` или `YANDEX_TOOLSETS`.

Клиенты и `notifications/tools/list_changed` (проверено по официальной документации, changelog или заявлениям мейнтейнеров, 2026-10):

| Клиент | `tools/list_changed` | Источник |
|---|---|---|
| Claude Code | Да (интерактивно: tools, prompts, resources; `-p`/Agent SDK: только tools) | [docs: Dynamic tool updates](https://code.claude.com/docs/en/mcp) |
| VS Code (GitHub Copilot) | Да (dynamic tool discovery); новые инструменты могут стать доступны агенту только со следующего хода | [docs](https://code.visualstudio.com/api/extension-guides/ai/mcp), [#303012](https://github.com/microsoft/vscode/issues/303012) |
| Gemini CLI | Да (обновляет реестр инструментов) | [PR #14375](https://github.com/google-gemini/gemini-cli/pull/14375), [PR #21050](https://github.com/google-gemini/gemini-cli/pull/21050) |
| Cursor | Ненадёжно: регрессия в 3.12.x подтверждена командой Cursor; после включения перезапустите Cursor | [forum](https://forum.cursor.com/t/mcp-server-regression-does-not-reload-tools-disconnect-does-nothing-ignores-mcp-json-changes-etc/166216) |
| Claude Desktop, Windsurf, Codex CLI, Cline, Zed, Continue | Не проверено: официальных данных нет; используйте `eager` или переподключитесь после включения | — |

## Поддержка и обновления

- Проект активно поддерживает ZAI.ONE: текущая версия 0.6.0; изменения в [CHANGELOG.md](CHANGELOG.md) и [Releases](https://github.com/zai-one/yandex-mcp/releases).
- Встроенная проверка обновлений: попросите ассистента вызвать `yandex_check_update` (публичный GitHub API, без учётных данных, с кэшем; ничего не устанавливается автоматически; отключение: `YANDEX_DISABLE_UPDATE_CHECK=1`).
- Следует актуальным практикам MCP: аннотации инструментов (read-only / destructive), наборы инструментов и режим только чтения, `instructions` сервера, промпты и ресурсы, структурированные ошибки с подсказками, секреты не попадают в ответы, бюджет токенов описаний проверяется в тестах, а eval маршрутизации проверяет, что 23 «живых» запроса (RU/EN) доходят от короткого роутера до нужного навыка, справочника и инструмента.
- CI прогоняет тесты на Linux и Windows для каждого pull request.

## Установка

**За минуту** (установлены Python 3.12+ и uv, есть OAuth-токен Метрики):

```sh
git clone https://github.com/zai-one/yandex-mcp.git && cd yandex-mcp
uv sync --frozen --extra standalone
uv run --frozen --extra standalone python scripts/configure.py   # токен вводится в скрытом поле
```

Добавьте созданный `mcp-client.json` в клиент (Claude Desktop, Cursor...), перезапустите его и спросите: *«Покажи мои счётчики Метрики»*. Совет: `"YANDEX_TOOLSETS": "default"` в env уменьшает список инструментов; остальное ассистент найдёт через роутер (`yandex://guide/tool-map`). Подробности ниже.


Хотите установить готовый пакет? [Установка релиза и создание конфигурации клиента](INSTALL.md#install-a-release-package) работают без клонирования исходников.

Нужны **Python 3.12–3.14** и [uv](https://docs.astral.sh/uv/getting-started/installation/). Можно клонировать проект через Git или [скачать ZIP](https://github.com/zai-one/yandex-mcp/archive/refs/heads/main.zip). Для ZIP откройте распакованный каталог и пропустите первые две команды.

У каждой группы API свои учётные данные. Настройщик начинает с Метрики; для Директа, Аудиторий, Вебмастера и Yandex Cloud добавьте доступы к нужным сервисам. Для Cloud Search также нужен ID каталога. См. [настройку сервисов](INSTALL.md#from-a-clone-or-source-zip) и [контракт безопасности Аудиторий](docs/AUDIENCE.md).

```sh
git clone https://github.com/zai-one/yandex-mcp.git
cd yandex-mcp
uv sync --frozen --extra standalone
uv run --frozen --extra standalone python scripts/configure.py
uv run --frozen --extra standalone yandex-mcp --config mcp.local.json --check-config
```

Настройщик создаёт локальную конфигурацию и сохраняет секреты в приватных файлах. Если конфигурация уже существует, он не перезапишет её. `--check-config` проверяет локальные настройки; доступ к аккаунту проверяется первым запросом ниже.

## Подключение к ассистенту

Добавьте конфигурацию в MCP-клиент, использующий раздел `mcpServers` (например, Claude Desktop или Cursor). Замените `/ABSOLUTE/PATH/` своим абсолютным путём; на Windows в JSON можно использовать `D:/Tools/`.

```json
{
  "mcpServers": {
    "yandex": {
      "command": "uv",
      "args": [
        "--directory",
        "/ABSOLUTE/PATH/yandex-mcp",
        "run",
        "--frozen",
        "--extra",
        "standalone",
        "yandex-mcp",
        "--config",
        "/ABSOLUTE/PATH/yandex-mcp/mcp.local.json"
      ]
    }
  }
}
```

Клиент сам запускает MCP-сервер. После обновления списка инструментов отправьте первый запрос. Для другого формата конфигурации используйте те же `command` и `args`; `uv` должен быть доступен процессу клиента.

### Первый запрос

> Покажи мои счётчики Метрики и цели выбранного счётчика.

Базовая настройка начинается с Метрики. Если её токен принят, ассистент сможет показать доступные счётчики и прочитать их цели. Остальные группы API используют отдельно настроенные учётные данные.

Если инструменты не появились, проверьте абсолютный путь, доступность `uv` и результат `--check-config`. Для ошибки доступа проверьте учётные данные и права аккаунта. [Подробная установка и диагностика](INSTALL.md).

## Несколько аккаунтов и агентства

Укажите в `YANDEX_ACCOUNTS_FILE` JSON-файл с именованными профилями. Незаданные поля наследуют базовые доступы, поэтому клиент агентства — это просто `direct_client_login`; отдельный аккаунт ссылается на свои файлы токенов (права только владельца, пути относительно JSON, токены не пишутся в сам файл).

```json
{
  "default": "client-a",
  "accounts": {
    "client-a": {"direct_client_login": "client-a-login", "description": "Клиент агентства A"},
    "shop-b": {"direct_token_file": "shop-b.direct.token", "metrika_token_file": "shop-b.metrika.token"}
  }
}
```

После этого у каждого инструмента появляется необязательный аргумент `account`, а `yandex_list_accounts` показывает профили без секретов. Без `account` используется `default` (или базовые доступы). Без файла ничего не меняется. Логины клиентов агентства — через `direct_list_agency_clients`.

Запись изолирована по аккаунтам: ключи идемпотентности, журнал записей и согласования принадлежат аккаунту, выбранному для вызова (Direct, Metrika, Webmaster, Audience), поэтому ключ или согласование одного аккаунта не повторяется и не применяется на другом. Записи без выбранного аккаунта сохраняют прежние ключи.

## Песочница Директа

`YANDEX_DIRECT_SANDBOX=true` направляет все вызовы Директа в официальную [Песочницу](https://yandex.ru/dev/direct/doc/ru/concepts/sandbox) (`api-sandbox.direct.yandex.com`, тестовые данные, тот же токен; включается один раз в Директе: Настройки API → Песочница). Сначала отрабатывайте изменения там; флаги записи и подтверждения продолжают действовать. Для отдельного аккаунта: `"direct_sandbox": true` в `YANDEX_ACCOUNTS_FILE`. Записи, ключи идемпотентности и подтверждения песочницы хранятся отдельно от боевых, поэтому репетиция никогда не засчитывается и не применяется как боевое изменение.

## Управление доступом и ограничения

Поисковым заданиям нужны отдельный worker и ID каталога Cloud. Wordstat использует доступы Cloud и явно заданные лимиты расходов. Запись зависит от прав сервиса и серверной политики. OAuth: `yandex_auth_start` / `yandex_auth_finish` (device-code, hot reload без перезапуска; только локальный stdio, на HTTP-сервере недоступны; `yandex://guide/oauth`) или `yandex-mcp-oauth --device`.

Для работы по сети предусмотрен HTTP с проверкой токенов. [Настройка HTTP](INSTALL.md#http), [конфигурация и права](docs/RUNTIME.md), [подключение Python-пакета](INSTALL.md#python-package-and-platform-integration).

## Обновления

Попросите ассистента вызвать `yandex_check_update`. Инструмент сравнивает установленную версию с
[последним релизом](https://github.com/zai-one/yandex-mcp/releases) через публичный GitHub API
(без токенов, без запросов к API Яндекса и расхода квот, таймаут 3 секунды, результат кэшируется на 24 часа рядом с файлом состояния)
и возвращает текущую и новую версии, ссылку на описание релиза и команду обновления
(`git pull --ff-only && uv sync --frozen --extra standalone` для клона, `uv tool install --force ...` для релизного пакета).
Если о новой версии уже известно из кэша, сервер один раз упоминает её в стартовых инструкциях.
Ничего не устанавливается автоматически. Без сети проверка возвращает `status: unknown`, а сервер продолжает работать.
Отключить: `YANDEX_DISABLE_UPDATE_CHECK=1`.
