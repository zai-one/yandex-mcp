# Yandex MCP

**Реклама, аналитика и поисковые данные Яндекса — в одном диалоге.**

> MCP-сервер для Яндекс Директа, Метрики (включая Logs API и офлайн-конверсии), Вебмастера, Wordstat, Search API и Аудиторий: 97 инструментов в одном сервере, наборы инструментов, режим только чтения и защищённая запись.

Разбирайте кампании Директа, статистику Метрики, ограниченные сценарии Аудиторий, поисковый спрос и диагностику Вебмастера с одним ассистентом. Yandex MCP объединяет шесть групп API: настройте нужные для вашей задачи сервисы и добавляйте остальные по мере необходимости.

[Установка](#установка) · [Подключение к ассистенту](#подключение-к-ассистенту) · [Issues](https://github.com/zai-one/yandex-mcp/issues)

Например, попросите ассистента:

> Покажи мои счётчики Метрики. Для выбранного счётчика сравни визиты и достижения целей за два равных периода и выдели самые заметные изменения.

## Что можно сделать

| Задача | Возможности MCP |
|---|---|
| Директ | Кампании, поддерживаемые рекламные объекты, пакетные стратегии и статистика, в том числе конверсии и доход по целям; управляемые изменения при включённой записи. |
| Метрика | Счётчики, цели, отчёты с фильтрами, сравнение периодов и CSV со сведениями о выборке. |
| Search API | Асинхронные задания поисковой выдачи Яндекса с сохранёнными результатами. |
| Wordstat | Популярные запросы, динамика спроса, распределение по регионам и дерево регионов. |
| Вебмастер | Индексация и диагностика сайта, история ИКС, важные страницы, события появления и исключения страниц, статистика запросов, работа с sitemap и переобходом. |
| Аудитории | Сегменты и пиксели; защищённое создание окружностей, полигонов, пикселей и сегментов зрителей при явном включении. |

[Примеры отчётов и помощь с OAuth](docs/METRIKA_REPORTS.md#по-русски): сравнение периодов, экспорт и объяснение неполных результатов. [Покрытие API](docs/API_COVERAGE.md#по-русски): новые инструменты со ссылками на документацию Яндекса.

## Почему этот MCP

- Шесть групп API Яндекса в одном процессе; включайте только нужные наборы (`YANDEX_TOOLSETS`, `YANDEX_READ_ONLY`). Редкие чтения — в отдельных наборах `direct_extra` (клиент, справочники, Changes, ставки, корректировки, аудитории, ретаргетинг, фиды, креативы, уточнения, турбо-страницы, лиды, видео, наборы минус-фраз) и `webmaster_extra` (владельцы, фиды, регионы, аналитика запросов); по умолчанию они не включены.
- Запись (изменения в Директе, создание сегментов Аудиторий, загрузки и Logs-запросы Метрики) выключена, пока не включена переменной окружения, и использует хэши подтверждения или ключи идемпотентности.
- Агентский слой: инструкции-роутер, 4 промпта, ресурсы `yandex://playbook` и гайды, самодостаточные skills, структурированные ошибки с `hint`.
- Сравнение с другими Yandex MCP на GitHub: [SvechaPVL/yandex-mcp](https://github.com/SvechaPVL/yandex-mcp) (132 инструмента) и [skiddgoddamn/yandex-marketing-mcp](https://github.com/skiddgoddamn/yandex-marketing-mcp) (153) покрывают больше методов; этот сервер делает ставку на ограниченные типизированные ответы, отдельные шлюзы записи по сервисам и установку, проверенную в CI.

## Поддержка и обновления

- Проект активно поддерживает ZAI.ONE: текущая версия 0.5.1; изменения в [CHANGELOG.md](CHANGELOG.md) и [Releases](https://github.com/zai-one/yandex-mcp/releases).
- Встроенная проверка обновлений: попросите ассистента вызвать `yandex_check_update` (публичный GitHub API, без учётных данных, с кэшем; ничего не устанавливается автоматически; отключение: `YANDEX_DISABLE_UPDATE_CHECK=1`).
- Следует актуальным практикам MCP: аннотации инструментов (read-only / destructive), наборы инструментов и режим только чтения, `instructions` сервера, промпты и ресурсы, структурированные ошибки с подсказками, секреты не попадают в ответы, бюджет токенов описаний проверяется в тестах.
- CI прогоняет тесты на Linux и Windows для каждого pull request.

## Установка

Хотите установить готовый пакет? [Установка релиза и создание конфигурации клиента](INSTALL.md#install-a-release-package) работают без клонирования исходников.

Нужны **Python 3.12–3.14** и [uv](https://docs.astral.sh/uv/getting-started/installation/). Можно клонировать проект через Git или [скачать ZIP](https://github.com/zai-one/yandex-mcp/archive/refs/heads/main.zip). Для ZIP откройте распакованный каталог и пропустите первые две команды.

У каждой группы API свои учётные данные. Настройщик начинает с Метрики; для Директа, Аудиторий, Вебмастера и Yandex Cloud добавьте доступы к нужным сервисам. Для Cloud Search также нужен ID каталога. См. [настройку сервисов](INSTALL.md#from-a-clone-or-source-zip) и [контракт безопасности Аудиторий](docs/AUDIENCE.md).

```sh
git clone https://github.com/zai-one/yandex-mcp.git
cd yandex-mcp
uv sync --frozen --extra standalone
uv run --frozen --extra standalone python scripts/configure.py
uv run --frozen --extra standalone yandex-mcp --config mcp.local.json --check-config
```

Настройщик создаёт локальную конфигурацию и сохраняет секреты в приватных файлах. Если конфигурация уже существует, он не перезапишет её. `--check-config` проверяет локальные настройки; доступ к аккаунту проверяется первым запросом ниже.

## Подключение к ассистенту

Добавьте конфигурацию в MCP-клиент, использующий раздел `mcpServers` (например, Claude Desktop или Cursor). Замените `/ABSOLUTE/PATH/` своим абсолютным путём; на Windows в JSON можно использовать `D:/Tools/`.

```json
{
  "mcpServers": {
    "yandex": {
      "command": "uv",
      "args": [
        "--directory",
        "/ABSOLUTE/PATH/yandex-mcp",
        "run",
        "--frozen",
        "--extra",
        "standalone",
        "yandex-mcp",
        "--config",
        "/ABSOLUTE/PATH/yandex-mcp/mcp.local.json"
      ]
    }
  }
}
```

Клиент сам запускает MCP-сервер. После обновления списка инструментов отправьте первый запрос. Для другого формата конфигурации используйте те же `command` и `args`; `uv` должен быть доступен процессу клиента.

### Первый запрос

> Покажи мои счётчики Метрики и цели выбранного счётчика.

Базовая настройка начинается с Метрики. Если её токен принят, ассистент сможет показать доступные счётчики и прочитать их цели. Остальные группы API используют отдельно настроенные учётные данные.

Если инструменты не появились, проверьте абсолютный путь, доступность `uv` и результат `--check-config`. Для ошибки доступа проверьте учётные данные и права аккаунта. [Подробная установка и диагностика](INSTALL.md).

## Несколько аккаунтов и агентства

Укажите в `YANDEX_ACCOUNTS_FILE` JSON-файл с именованными профилями. Незаданные поля наследуют базовые доступы, поэтому клиент агентства — это просто `direct_client_login`; отдельный аккаунт ссылается на свои файлы токенов (права только владельца, пути относительно JSON, токены не пишутся в сам файл).

```json
{
  "default": "client-a",
  "accounts": {
    "client-a": {"direct_client_login": "client-a-login", "description": "Клиент агентства A"},
    "shop-b": {"direct_token_file": "shop-b.direct.token", "metrika_token_file": "shop-b.metrika.token"}
  }
}
```

После этого у каждого инструмента появляется необязательный аргумент `account`, а `yandex_list_accounts` показывает профили без секретов. Без `account` используется `default` (или базовые доступы). Без файла ничего не меняется. Логины клиентов агентства — через `direct_list_agency_clients`.

Запись изолирована по аккаунтам: ключи идемпотентности, журнал записей и согласования принадлежат аккаунту, выбранному для вызова (Direct, Metrika, Webmaster, Audience), поэтому ключ или согласование одного аккаунта не повторяется и не применяется на другом. Записи без выбранного аккаунта сохраняют прежние ключи.

## Управление доступом и ограничения

Поисковым заданиям нужны отдельный worker и ID каталога Cloud. Wordstat использует доступы Cloud и явно заданные лимиты расходов. Запись зависит от прав сервиса и серверной политики. Интерактивная настройка OAuth и экспорт Metrika Logs не включены.

Для работы по сети предусмотрен HTTP с проверкой токенов. [Настройка HTTP](INSTALL.md#http), [конфигурация и права](docs/RUNTIME.md), [подключение Python-пакета](INSTALL.md#python-package-and-platform-integration).

## Обновления

Попросите ассистента вызвать `yandex_check_update`. Инструмент сравнивает установленную версию с
[последним релизом](https://github.com/zai-one/yandex-mcp/releases) через публичный GitHub API
(без токенов, без запросов к API Яндекса и расхода квот, таймаут 3 секунды, результат кэшируется на 24 часа рядом с файлом состояния)
и возвращает текущую и новую версии, ссылку на описание релиза и команду обновления
(`git pull --ff-only && uv sync --frozen --extra standalone` для клона, `uv tool install --force ...` для релизного пакета).
Если о новой версии уже известно из кэша, сервер один раз упоминает её в стартовых инструкциях.
Ничего не устанавливается автоматически. Без сети проверка возвращает `status: unknown`, а сервер продолжает работать.
Отключить: `YANDEX_DISABLE_UPDATE_CHECK=1`.
